Plot Flow — это форк открытой программы **Handy** (cjpais/Handy, лицензия MIT): Rust + Tauri 2 + React + Tailwind.
~27 000 строк Rust и ~15 000 строк TypeScript. Распознавание — модель **GigaAM v3 (Сбер)** в формате GGUF
через библиотеку `transcribe-cpp` (ggml, GPU через Vulkan), детектор речи Silero VAD. Всё работает локально, интернет не нужен.

### Почему «ломается» длинная диктовка — причина найдена
Лог программы говорит прямо:

```
[WARN] gigaam run: audio is 163.9 s, beyond the ~25 s window this model was trained on;
transcription may be degraded. Split long audio into <=25 s segments.
```

Модель GigaAM обучена на отрезках до **25 секунд**. Программа отдаёт ей запись **целиком** (у вас сегодня были
записи по 57, 72, 92, 98 и 164 секунды). Чем длиннее запись, тем сильнее модель «уплывает» и выдаёт ломаный текст.
Скриншоты и интернет ни при чём: ломает сама длина.

**Как чинится:** резать запись по паузам на куски ≤ 25 с и распознавать по кускам, склеивая текст.
Готовый механизм для этого (`VadChunked` в библиотеке `transcribe-rs`) уже есть среди зависимостей проекта —
его просто не подключили к GigaAM.

Это подтверждено и в исходном проекте Handy: в их issue/PR #1362 описано то же самое — «GigaAM-v3 выдаёт
бессмыслицу на записях дольше ~60 с», лечение — резка по Silero VAD на куски ≤ 30 с. Авторы Handy это исправление
отложили, так что делаем сами.

### Почему «э-э» и «а-а» остаются в тексте
В коде удаления слов-паразитов есть списки только для английского, немецкого и французского.
Для русского списка **нет** — удаляются лишь «хм» и «ммм». Надо добавить русский набор («э», «э-э», «ээ», «эм», «а-а», «м-м» и т. п.;
одиночную «а» трогать нельзя — это союз).

### Что ещё важно про машину
- **На диске C: свободно 0,9 ГБ.** Собрать программу в таком состоянии невозможно. 19 ГБ занимает старый

- Предыдущие сборки падали из-за нехватки памяти; собирать нужно в один поток (это уже настроено в проекте, ~11 минут).

## 2. Готовые решения, на которых строим

Хорошая новость: почти всё нужное уже лежит в зависимостях проекта или доступно бесплатно и локально.

| Задача | Решение | Статус |
|---|---|---|
| Кто говорит (разделение голосов в реальном времени) | **NVIDIA Sortformer** (streaming, до 4 говорящих) — поддержка уже встроена в `transcribe-cpp`, модель готова на Hugging Face (`handy-computer/diar_streaming_sortformer_4spk-v2.1-gguf`) | есть, нужно подключить |
| Запись звука компьютера (Telegram, Telemost, Zoom) | **WASAPI loopback** — поддерживается библиотекой `cpal` 0.16, которая уже используется | есть, нужно подключить |
| Резка длинного аудио по паузам | `VadChunked` из `transcribe-rs` | есть, нужно подключить |
| Голосовые профили («Максим», «Алексей») | Библиотека **sherpa-onnx** (официальный Rust-пакет, Apache-2.0): готовый «менеджер голосов» — добавить голос, найти ближайший, проверить. Модели отпечатков 3D-Speaker CAM++ / WeSpeaker (~28 МБ), языконезависимые | есть, нужно подключить |
| «Робот»: резюме созвона, темы, решения, задачи | Существующий модуль `llm_client.rs` понимает любой OpenAI-совместимый сервер → подключаем **Ollama** или **LM Studio**. Модель: **T-lite-it-2.1** (Т-Банк, на базе Qwen3-8B, Apache-2.0, лучшая из открытых по русскому в своём размере, ~5 ГБ); «качественный» вариант — Qwen3-14B (~9 ГБ, впритык) | есть, нужны пресеты и кнопка |
| Усиление микрофона на максимум при записи | Windows Core Audio `IAudioEndpointVolume` (нужная часть `windows`-crate уже подключена) + программная нормализация громкости | добавить |
| Защита от потери записи | Схема Meetily: писать аудио на диск кусками по 30 с и сохранять текст после каждого куска; при запуске предлагать восстановить | добавить |

### Открытые проекты-ориентиры (код можно изучать и заимствовать, лицензия MIT)
- **Hyprnote** (Tauri + Rust, 9,8 тыс. звёзд) — ближайший по архитектуре: микрофон + звук системы с синхронизацией и эхоподавлением, локальная диаризация, LLM через Ollama/LM Studio.

## 3. План работ по этапам

Порядок выбран так, чтобы **сначала убрать страх потерять текст**, потом переделать оболочку, потом строить «Совещание».
Каждый этап заканчивается рабочим установщиком.

### Этап 0 — подготовка (полдня)
1. Удалить кэш `src-tauri\target\debug` (освободит 19 ГБ). Папка `release` с архивами ваших данных не трогается.
2. Перенести репозиторий в `C:\Moksem\P3-plot-flow` (сейчас путь с кириллицей и длинным тире ломает часть инструментов). Папка на рабочем столе остаётся как резерв.
3. Создать ветку `v2`, собрать текущую версию как есть — убедиться, что сборка проходит.

### Этап 1 — надёжная диктовка (1–2 дня) → версия 1.3
- Резка записи по паузам на куски ≤ 25 с перед GigaAM; склейка текста. Тест на реальных ваших записях из `Data\recordings`.
- Русский список слов-паразитов; схлопывание повторов «а а», «э э».
- Авто-усиление микрофона: при старте записи выставлять уровень 100 % и нормализовать громкость программно; возвращать как было после.
- Страховка: аудио пишется на диск по ходу записи, а не только в конце; при падении программы запись не теряется.
- Ограничение «одна запись — не дольше N минут» с предупреждением (по умолчанию 10 мин; созвоны пойдут через отдельный режим).

### Этап 2 — новая оболочка (2–3 дня) → версия 1.4
- Окно **фиксированного размера**, без изменения размера и максимизации. Предлагаю 1000 × 680 (под него верстается всё остальное; обсуждаем).
- **Тёмная тема по умолчанию** + светлая на выбор; единые цвета, отступы, типографика (сохраняем зелёный `#96a36c` как акцент и логотип).
- Меню слева: **Диктовка · Совещания · История · Статистика · Настройки**.
- Настройки сгруппировать, экспериментальные и отладочные убрать с глаз.

### Этап 3 — «Совещание», базовая версия (4–6 дней) → версия 2.0
- Экран с одной большой кнопкой записи, таймером, индикатором уровня двух дорожек (микрофон / звук компьютера), пауза/стоп.
- Одновременная запись микрофона и звука компьютера (loopback). Дорожка «Я» и дорожка «Собеседники».
- **Живой транскрипт**: текст появляется по ходу разговора (GigaAM по паузам, кусками 5–25 с).
- **Кто говорит**: Sortformer делит на «Говорящий 1 / 2 / 3 / 4»; клик по метке → переименовать, имя применяется ко всем репликам.
- Сохранение по кускам 30 с + восстановление после сбоя; авто-стоп после 15 мин тишины.
- Созвоны хранятся в базе; экспорт **TXT, Markdown, JSON, SRT** с именами и временем.
- Многочасовые записи: проверка на 2–3 часах непрерывной записи.

### Этап 4 — голосовые профили (2–3 дня) → версия 2.1
- «Создать роль»: имя → программа показывает случайную фразу → человек её читает → сохраняется голосовой отпечаток (sherpa-onnx, модель CAM++).
- Во время созвона для каждого отрезка речи считается отпечаток и ищется ближайший известный голос; вместо «Говорящий 2» сразу пишется «Максим».
  Этот способ не зависит от языка — надёжнее, чем полагаться только на Sortformer (он обучен на английском). Sortformer остаётся для разделения незнакомых голосов и наложений.
- Профили хранятся локально, можно удалить.

### Этап 5 — «Робот» (2–3 дня) → версия 2.2
- Кнопка с иконкой робота на экране созвона и в истории. Пресеты: *Краткое резюме · Темы · Решения · Задачи и ответственные · Открытые вопросы · Теги · Что интересовало собеседников · Свой запрос*.
- Работает через локальный сервер (Ollama / LM Studio) — модель T-lite-it-2.1 (по умолчанию) или Qwen3-14B. Если сервер не запущен, программа подсказывает, как поставить.
- Результат сохраняется рядом с транскриптом, пункты резюме кликабельны и ведут к месту в тексте.
- (Позже) встроить llama.cpp прямо в программу, чтобы ничего не ставить отдельно.

### Этап 6 — статистика и мелочи (1–2 дня) → версия 2.3
- **Топ-10 слов** — это не гигантская база: ведём счётчик слов по дням в той же SQLite, это килобайты. Делаем.
- Слов в минуту, серия дней подряд, «сэкономлено времени», статистика по созвонам.
- Личный словарь: одно нажатие — добавить слово, которое модель коверкает.

**Итого:** ~3–4 недели работы, 6 промежуточных релизов. Этапы 1–2 дают ощутимый результат уже в первую неделю.

## 5. Обзор рынка (кратко)

**Как захватывают звук.** Три подхода: бот заходит в звонок (Otter, Fireflies, tl;dv, Fathom, Mymeet, Timelist);
локальная запись звука системы + микрофона без бота (Granola, Notion, Krisp, MacWhisper); запись встроенными средствами платформы
(Teams Copilot, Zoom AI Companion, SaluteJazz, МТС Линк, Контур.Толк, Телемост). Нам подходит второй — он не зависит от сервиса, в котором идёт звонок.

**Как определяют говорящих.** Почти все: автоматические «Говорящий 1/2» + переименование вручную; Otter запоминает голос после первой разметки
(голосовой отпечаток — то, что вы описали кодовой фразой); Granola берёт имена из Zoom/Meet/Teams; Google Recorder удаляет голосовые модели после разметки.

**Структура резюме** (повторяется у всех): Обзор → Темы с таймкодами → Решения → Задачи (ответственный, срок) → Открытые вопросы. Плюс чат «спроси у транскрипта».

**Экспорт**: TXT, DOCX, SRT, Markdown, JSON (Fireflies, Otter, Notta, Mymeet).

**Надёжность длинных записей**: Meetily пишет куски по 30 с и JSON после каждого куска; при запуске — «Восстановить потерянную запись?». Истории потерь часовых записей в Zoom показывают, зачем это нужно.

**Диктовка**: Wispr Flow и Typeless удаляют паразиты и повторы по умолчанию, ведут личный словарь; статистика — слов/мин, серия дней, сетка активности, «самое частое слово» (Wispr Voice Profile).

Российские продукты: Яндекс Телемост (конспект YandexGPT), SaluteJazz (итоги встречи, транскрипт по говорящим), МТС Линк (задачи с ответственными),
Контур.Толк (пересказ + протокол с решениями, DOCX/TXT), Timelist (диаризация, протокол, чат по встречам, on-premise), Mymeet.ai (бот + шаблоны отраслей, DOCX/MD/JSON/PDF).

## 6. Риски и честные оговорки

- Sortformer обучен в основном на английской речи; на русском разделение голосов работает, но точность надо проверить на реальных созвонах. Поэтому именные роли строятся на голосовых отпечатках (этап 4), а Sortformer — вспомогательный.
- Звук системы захватывается только в общем режиме (всё, что играет компьютер): музыка в фоне тоже попадёт в транскрипт. Захват «только Telegram» возможен (Windows 10 2004+), но сложнее — отложим.
- Звук из Telegram/Telemost идёт одной дорожкой: несколько собеседников в ней различаются только Sortformer'ом/отпечатками, а не по источнику.
- GigaAM не умеет пунктуацию «из коробки» так же хорошо, как Whisper; возможно, для созвонов пригодится вторая модель (Whisper large-v3-turbo есть в том же каталоге) — решим после тестов на этапе 3.
- Компьютер слабый по памяти: сборки долгие; разработку веду так, чтобы не мешать вашей работе (сборки в фоне, одна за раз).
